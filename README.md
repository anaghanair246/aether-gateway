# 🌌 Aether Gateway

**Aether Gateway** is an intelligent, edge-native LLM proxy designed to optimize the financial Pareto frontier (Cost vs. Quality) of Large Language Models. 

Unlike traditional API gateways that rely on static, rule-based routing, Aether embeds a highly calibrated, ultra-fast Machine Learning classifier directly into the network path. It dynamically predicts the complexity of a prompt in under 15ms and routes it to the most cost-effective model capable of answering it, backed by an intent-aware semantic cache.

This project was built as a machine learning systems thesis demonstrating cost reduction and latency optimization in distributed LLM architectures.

---

## ✨ Core Features & Novelty

*   **Pre-Execution Predictive ML Router:** Uses a fine-tuned DistilBERT model exported to ONNX. It evaluates prompt complexity (logits and Softmax probabilities) before making API calls, ensuring high-quality responses while heavily reducing costs.
*   **Intent-Aware Semantic Caching:** Utilizes PostgreSQL and `pgvector` to store vector embeddings of past prompts. The cache operates with dynamic thresholds to prevent "cache poisoning" and false-positive hits on strict coding/math tasks.
*   **Telemetry & Calibration:** Outputs Expected Calibration Error (ECE) metrics, router confidence percentages, and granular latency tracking (Router ms vs. LLM ms) for academic benchmarking.
*   **Live Interactive UI:** Includes a Streamlit dashboard that visualizes the chat interface alongside real-time gateway telemetry (latency, routed tiers, cache hits, and raw logits).

---

## 🏗️ Architecture

1.  **Client/UI:** Streamlit Frontend (`ui.py`).
2.  **Gateway Backend:** FastAPI & Uvicorn (`main.py`).
3.  **ML Router:** ONNX Runtime executing a quantized DistilBERT classification graph (`router.py`).
4.  **Semantic Memory:** PostgreSQL with the `pgvector` extension (`database.py`).
5.  **LLM Backend:** Local models powered by Ollama (e.g., `qwen2.5:0.5b` for the "Cheap" tier, `qwen2.5:3b` for the "Strong" tier).

## ⚙️ Prerequisites

Before installing, ensure you have the following installed on your system:
*   **Python 3.10+**
*   **PostgreSQL** with the [`pgvector`](https://github.com/pgvector/pgvector) extension installed.
*   **Ollama** (or a similar local LLM provider) with your target models downloaded:
    ```bash
    ollama run qwen2.5:0.5b
    ollama run qwen2.5:3b
    ```

## 🚀 Installation

**1. Clone the repository:**
```bash
git clone https://github.com/yourusername/aether-gateway.git
cd aether-gateway
```

**2. Set up a Python Virtual Environment:**
```bash
python3 -m venv venv
source venv/bin/activate
```

**3. Install Dependencies:**
```bash
pip install fastapi uvicorn asyncpg onnxruntime transformers streamlit pandas requests torch
```
*(Note: If you are running on AMD ROCm or specialized hardware, ensure you install the correct PyTorch wheels for your system).*

**4. Database Configuration:**
Ensure your PostgreSQL instance is running. The application expects a database named `aether_db` accessible by the user `aether` with the password `password` on port `5432`.

To set this up quickly in `psql`:
```sql
CREATE DATABASE aether_db;
CREATE USER aether WITH ENCRYPTED PASSWORD 'password';
GRANT ALL PRIVILEGES ON DATABASE aether_db TO aether;
\c aether_db;
CREATE EXTENSION IF NOT EXISTS vector;
```

*(The Gateway will automatically create the required `semantic_cache` tables on startup).*

---

## 💻 Running the Gateway

The system requires two terminal windows to run the full microservice stack.

**Terminal 1: Start the FastAPI Backend**
```bash
source venv/bin/activate
uvicorn main:app --reload
```
*The backend will load the ONNX model and connect to the PostgreSQL database. It runs on `http://127.0.0.1:8000`.*

**Terminal 2: Start the Streamlit UI**
```bash
source venv/bin/activate
streamlit run ui.py
```
*The dashboard will automatically open in your browser at `http://localhost:8501`.*

## 🛠️ Utility Scripts

*   **`train_model.py`:** Trains the DistilBERT classifier from a balanced CSV dataset and exports it to a highly optimized ONNX graph.
*   **`test_onnx.py`:** A diagnostic script to verify the ONNX model's raw logits and ensure there is no gradient collapse.
*   **`clear_cache.py`:** A sanitation script that wipes the `pgvector` database to mitigate "cache poisoning" (hallucinated state retention) during benchmarking.
